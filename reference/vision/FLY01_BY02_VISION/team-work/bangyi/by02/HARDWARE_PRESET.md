# BY-02 视觉模块硬件预设

本文件对应本次 PC 视觉代码。目标是先用电脑已有的 Python、NumPy、Pillow 运行红色目标识别，并为同系列亚博 K230 的后续接入保留接口。

当前输出是视觉观测和项目接入提案；不发送 FPGA 报文，不控制电机。图片、GIF 和 K230 JSONL 文件回放均为离线输入，不能作为真实摄像头或实体闭环的验收证据。

## 1. 本次使用与预留的设备

| 部件 | 当前确认程度 | 本次预设 |
|---|---|---|
| Windows 电脑 | 已有 Anaconda，当前检查的 Python 为 3.13.9 | 运行识别、生成带标注图片和观测文件 |
| NumPy / Pillow | 当前环境中已有 | 图片与 GIF 的必要依赖 |
| OpenCV | 当前检查的环境中没有安装 | 可选视频文件／电脑摄像头入口；安装后再使用 |
| K230 | 此前照片给出 Yahboom / YB-KA02 系列线索 | 实物到位后核对 PCB 型号、固件、镜头和 USB 模式 |
| 达芬奇 A7 FPGA | 项目已有，本次未连接检测 | 由 Work 的主机端接入；本工具不改 FPGA 端点 |
| 电机及驱动 | 本次未连接检测 | 留给执行器适配与停止机制验收 |

Anaconda 是电脑上的 Python 环境；它不能证明 K230 中已安装哪一种固件，也不能证明 USB 已暴露摄像头服务。

## 2. 数据接洽预设

```text
本次可用：图片 / GIF
              ↓
       PC 红色目标检测
              ↓
      视觉观测 JSONL + 带框图片
              ↓
      项目反馈提案（默认 BLOCKED）

可选扩展：视频 / PC 摄像头 ── OpenCV ──┘

K230 后续：K230 采集与识别
              ↓  传输方式待核对与实现
       K230 JSONL 接收 / 回放适配
              ↓
       同一份视觉观测与接入提案
              ↓  Work 完成时钟、合同与时效检查
       PC 编码器 → O8 USB-UART → FPGA
              ↓
       DN / 冻结运动映射 → 执行器适配 → 电机
```

- 未来 K230 可以承担采集和环境信息提取。当前预留的是**观测消息接口**，没有提供已验证的 K230 固件或实时串口接收服务。
- K230 到 PC 的 USB 与 PC 到 FPGA 的 USB-UART 是两个独立连接，需要分别确认设备身份、用途和供电。
- K230 USB 可能用于供电、调试、固件下载或其他服务。只有确认固件提供 UVC 服务并通过枚举与采集测试后，才能把它当普通 USB 摄像头使用。
- 默认先通过 PC 接入 Work 的主机软件，不把 K230 GPIO 直接连接 FPGA 或电机驱动。
- 本项目冻结的神经编码器、DN 映射和 O8 报文由 Work 维护；本工具的图像坐标不能未经转换就写入该接口。

## 3. 集中配置位置

需要实物调整的项目集中在 `fly01_vision/settings.py`，旁边带有 `装车后调整` 或 `实物到位后调整` 注释。可以使用相同字段的 JSON 覆盖文件，保留代码默认值作为可复现基线。

| 配置项 | 默认值 | 实物到位后核对什么 |
|---|---|---|
| `input.rotation_deg` | `0` | 原始图像是否倒置／横置；取值为顺时针 `0/90/180/270` |
| `input.sensor_mirror_x` | `false` | 是否需要纠正相机原图的左右镜像；会改变识别坐标 |
| `input.preview_mirror_x` | `false` | 仅预览是否镜像；不改变输出的检测坐标 |
| `camera.index` | `0` | 电脑实际枚举的摄像头编号，不能当成固定 USB 端口号 |
| `camera.requested_width/height` | `640/480` | 只是请求值；按实际取得帧的宽高记录和重新标定 |
| `camera.requested_fps` | `20.0` | 只是请求值；测实际采集、处理与传输节拍 |
| `camera.max_frames` | `100` | 单次采集上限，依据测试时长调整 |
| `detector.red_min` | `150` | 红色通道最低值 |
| `detector.green_max/blue_max` | `110/110` | 绿色／蓝色通道最高值 |
| `detector.red_margin` | `70` | 红色相对其他通道的最小差值 |
| `detector.minimum_area_px` | `64` | 消除小噪点，按实际分辨率与目标距离调整 |
| `detector.image_center_deadband_px` | `2.0` | 图像中心附近的方向分类范围；单位为像素 |
| `freshness.max_processing_age_ms` | `250.0` | 本进程接收帧后的处理时长草案；由 Work 结合总时延验收 |

当前识别目标为红色目标卡片／色块，沿用 BY-01-R1 的阈值方法。它不是通用物体识别模型。现场光照、曝光、白平衡或目标颜色改变时，应先检查检测结果再改阈值。

## 4. 相机标定与安装预设

以下数值全部保留为 `null`，验证标志默认为 `false`：

- `calibration.width_px/height_px`：完成旋转与传感器镜像纠正后，参与识别的标定图像分辨率。
- `calibration.fx_px/fy_px/cx_px/cy_px`：对应这套镜头、分辨率和图像变换的实际内参。
- `calibration.intrinsics_verified`：确认内参来自实测标定后才置为 `true`。
- `calibration.rectified_input_verified`：输入已按对应标定结果去畸变后才置为 `true`。本程序不会仅凭该开关自动完成去畸变。
- `calibration.level_mount_verified`：当前简化模型要求相机水平安装；实测确认后才置为 `true`。
- `calibration.mount_yaw_rad`：相机光轴相对车头的偏航角，左转为正，单位为弧度。
- `calibration.mounting_verified`：安装方向、偏航角和坐标约定核对后才置为 `true`。

未完成标定时只输出像素中心和归一化图像偏移；`azimuth_rad`、单位射线、米制位置等未知字段保持 `null`。图像横坐标向右为正，项目机体坐标向左为正，不能直接复用符号。

完成方向标定后，简化模型可估计观察方向。**观察方向与米制目标位置是不同量**：单目颜色目标的中心不能直接提供距离。当前没有提供深度测量，米制位置仍保持未知；不会把单位射线当成米制位置。

标定后的观测也只进入提案审核，不自动开放控制。Work 还需核对真实采集时间、时钟映射、模型步号、完整反馈合同、测距来源及停止机制。

## 5. K230 的待确认项

| 项目 | 当前值／边界 | 后续操作 |
|---|---|---|
| `k230.board_hint` | 此前照片的系列提示 | 记录 PCB 完整型号和硬件修订号 |
| `k230.firmware` | `UNCONFIRMED` | 记录固件名称、版本、获取来源与启动方式 |
| `k230.camera_model` | `UNCONFIRMED` | 核对传感器、镜头与实际输出格式 |
| `k230.usb_application_mode` | `UNCONFIRMED` | 在电脑上检查枚举结果，确认供电／调试／应用接口 |
| `k230.transport` | `JSONL_FILE_REPLAY` | 当前只表示文件回放；实际传输完成并验收后另行实现 |
| 消息身份 | 预留会话与帧编号 | 确保重启更换会话，拒绝重复和倒序帧 |
| 采集时钟 | 尚未与 PC 映射 | 记录 K230 时钟来源、单位、重启行为和 PC 对时误差 |

此前说明书照片出现 UART3：GPIO32 对应 TX、GPIO33 对应 RX，12Pin 表中分别为 5、3 号脚。**这只是型号核对线索，不能作为本轮接线指令。** 装车前需同时核对实物丝印、对应版本原理图、固件引脚复用、逻辑电平和引脚占用。确认之前保持未接线。

K230 的引脚复用与 UART 使用应参照对应固件和板级资料，可参考 Kendryte 官方 [FPIOA 文档](https://www.kendryte.com/k230_canmv/en/main/example/peripheral/fpioa.html) 与 [UART 定时发送示例](https://www.kendryte.com/k230_canmv/en/main/example/peripheral/uart_periodic_tx.html)；示例中的引脚不能直接照搬到未知修订的板卡。

## 6. 供电和执行器边界

- 先核对板卡及外设实际输入电压、接口极性、稳态与峰值电流，再确定电源和线束。
- K230、FPGA 和电机电源如何分配应由装配与电源设计确认。不得从 FPGA／K230 GPIO 给电机供电；不把不同设备的电源输出直接并联。
- 默认使用设备认可的 USB／电源接口。需要 GPIO 通信时再设计电平匹配、地线及防反接措施。
- 本模块的 `stop_required` 是供下游处理的状态，不是硬件停机。真实执行器需独立看门狗与人工停止途径，断帧、失联和程序退出都应有可测的停机结果。
- 前进速度若由外部设定，应在记录中明确来源；本工具不生成神经前进命令。

详细实物调整顺序见同目录 `ASSEMBLY_TUNING.md`。
