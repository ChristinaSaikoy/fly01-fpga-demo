# 装车后的视觉调整与核对

本清单用于 K230、底盘与执行器实际到位后继续调试。当前图片／GIF／JSONL 回放用于验证视觉软件和字段，不代表实物已采集或小车已闭环运行。

配置集中在 `fly01_vision/settings.py`。搜索 `装车后调整` 和 `实物到位后调整` 可找到需要核对的位置；推荐保存独立的现场 JSON 覆盖文件，同时记录日期、设备、镜头、光照和软件版本。

## 一、先测量并记录

| 对象 | 需要实测或查证的项目 | 影响 |
|---|---|---|
| K230 外壳与支架 | 长宽高、重量、安装孔径和孔距、镜头相对安装面的坐标 | 支架、视野遮挡、重心与装配空间 |
| FPGA 板卡及固定件 | 含接头的外形尺寸、安装孔、接口朝向和散热空间 | 底盘布置、线束路径 |
| 底盘 | 可用安装平面、孔位、轮子与车体运动范围、承重、重心位置 | 避免线束擦轮及支架干涉 |
| 相机安装 | 镜头离地高度、横向与前后偏移、光轴偏航、俯仰和横滚 | 坐标转换与方向标定 |
| USB／电源线 | 插头外形、插入与弯折空间、所需长度、固定点 | 避免拉扯接口或进入车轮 |
| 供电 | 各设备输入电压、极性、正常与峰值电流、接头规格 | 电源与线径选择、掉电排查 |
| 相机输出 | 实际宽高、像素格式、帧率、镜像及曝光／白平衡行为 | 阈值、处理负载与标定适用性 |

未测尺寸统一记录为“待测”，不要按示意图推断螺孔位置。相机安装偏移可先登记在装配记录中；当前方向模型只实现水平安装和偏航修正，没有实现完整六自由度外参及米制目标定位。

## 二、先让单帧方向正确

1. 固定相机与目标卡，电机保持禁用。保存一张原始帧。
2. 将带有文字／箭头的测试卡摆正，核对画面上下和左右。
3. 在 `input.rotation_deg` 中选择顺时针 `0/90/180/270`。
4. 必要时修改 `input.sensor_mirror_x`，纠正进入检测的原始图像左右镜像。
5. 将目标依次放到物理左侧、正中、物理右侧。确认保存图像、像素中心与图像方向分类一致，并记录相机面朝方向。
6. `input.preview_mirror_x` 只用于观看习惯；不要依靠预览镜像修正控制坐标。

图像坐标约定为 x 向右、y 向下。项目机体坐标约定为 x 向前、y 向左、z 向上；相机未经安装标定时，“图像左侧”不能直接升级为已验证的机体方向。

## 三、确认实际分辨率和识别阈值

1. 有 PC 摄像头时，先确认 `camera.index`。K230 先确认固件和 USB 应用模式，不能仅靠连接 USB 就套用这个编号。
2. 按需设定 `camera.requested_width/height/fps`；检查实际取到帧的尺寸与可用节拍。默认 `640×480、20 fps` 只是演示请求值。
3. 使用预计装车的目标卡、距离和现场照明保存样本，至少包含：左、右、中间、无目标、消失后重现、多目标。
4. 对照带框图与 JSONL 中的目标数量、面积和中心，按需要调整 `detector.red_min/green_max/blue_max/red_margin`。
5. 调整 `detector.minimum_area_px` 排除小噪点，同时检查最远目标仍能保留。不要只靠增大面积阈值掩盖大面积红色背景。
6. 核对 `detector.image_center_deadband_px` 在实际图像大小下的效果；它属于图像分类参数，不是神经编码器的角度阈值。

本检测器识别红色色块，多个有效目标时保留多目标状态，不把任意一块自动当成已确认的跟踪对象。若现场需要另一类目标，应另行确定检测方案和样本，不能把颜色阈值识别说成通用视觉识别。

## 四、完成方向标定后再填参数

1. 用实际镜头、分辨率和最终图像变换进行相机标定，填写 `calibration.width_px/height_px/fx_px/fy_px/cx_px/cy_px`。
2. 明确原图是否去畸变。当前处理流程不自动去畸变；只有真实输入已经完成对应校正，才能设置 `rectified_input_verified=true`。
3. 当前模型要求相机光轴水平。实测确认后再设置 `level_mount_verified=true`；有明显俯仰／横滚时，应先扩展外参模型。
4. 测量相机光轴相对车头的偏航，填写 `mount_yaw_rad`（左转为正，单位 rad）。确认后设置 `mounting_verified=true`。
5. 确认内参来源、分辨率及图像处理一致后，再设置 `intrinsics_verified=true`。
6. 用车体左、前、右方向的已知目标位置复核角度符号与数量级。更换镜头、裁剪、分辨率、旋转或镜像策略后，重新检查标定是否仍适用。

方向标定只允许给出观察射线和方向角。**距离和米制位置仍需独立的测距／几何方案**；当前 `distance_m` 和 `relative_position_body_m` 保持 `null`。不要把标定开关全置为 `true` 来绕过接入阻塞。

## 五、K230 到位后的接入顺序

1. 拍摄 PCB 型号、硬件版本和接头丝印，记录摄像头型号。
2. 记录固件名称、版本、烧录来源与运行环境，更新 `k230` 设置。
3. 在电脑上确认 USB 枚举结果，区分供电、调试、下载和应用数据接口。
4. 如设备提供 UVC，先验证真实图像采集；如提供串口／网络观测，先保存消息文件并通过本项目 JSONL 回放校验。
5. 实现在线传输时，明确消息格式、会话编号、递增帧号、实际宽高、采集时间单位、时钟域以及连接中断处理。
6. K230 和 PC 的单调时钟不能直接相减。先设计时钟映射与误差测量，再由 Work 审核“采集至应用”的完整时效；PC 接收时间不能冒充相机曝光时间。
7. 真实在线接收、重连、重复帧、倒序帧和失联测试通过后，再提交 Work 做反馈适配。

当前 `k230.transport=JSONL_FILE_REPLAY` 明确表示离线回放。修改配置文字不会实现实时传输，也不会解除控制阻塞。GPIO UART 引脚仅见于此前说明书照片；接线需要对应原理图、复用配置、逻辑电平和供电方案的核验。

## 六、检查时效和停止责任

`freshness.max_processing_age_ms=250` 是视觉处理时长草案，约束本进程接收帧后到处理完成的时间。它不能证明 USB 缓冲前的画面新鲜，也不是执行器的电机看门狗。

- 测量采集、接收、处理、编码、FPGA、执行器各段的延迟与抖动，再确定可接受阈值。
- 连续服务需要调用者周期性检查新鲜度；`poll()` 不是自动运行的后台定时器。
- 进程退出后，本程序不能继续发停止请求。执行器侧必须能够独立处理失联与超时。
- 本程序的 `stop_required=true`、`eligible_for_live_control=false` 是接洽边界，不能由显示界面自行覆盖为电机使能。
- 无目标、多目标、过期、重复／倒序、输入结束或接收错误时，下游应拒绝旧观测并按独立停止策略处理。神经输入归零不能当成已验证的刹车。
- 低速实物测试前，先验证急停、上电默认禁用、断线停止和重新使能过程，记录停止时间和负责模块。前进速度若由人工或工程控制器设定，需要在演示中说明。

## 七、建议保留的装配后记录

每次实物测试保留：设备／固件身份、配置覆盖文件、原始帧、带框帧、观测 JSONL、项目提案、异常记录和测量条件。至少复核：

| 场景 | 需要看到的结果 |
|---|---|
| 单目标左／中／右 | 中心位置、图像方向、镜像预览和标定方向分别正确 |
| 无目标／多目标 | 观测状态明确，未输出伪造的唯一目标 |
| 目标消失后重现 | 消失期间不继续沿用旧中心，重现产生新帧记录 |
| 输入结束／程序退出／USB 断开 | 输入状态结束；执行器侧独立停止经过实测 |
| 延迟／重复／倒序消息 | 标记或拒绝，原始消息和原因可追查 |
| 更换分辨率／镜头／安装角度 | 原标定不被静默复用，重新记录与确认 |

最终由 Work 把视觉帧绑定到神经模型步号，核对完整反馈合同及 O8 主机端接入。该步骤与展示页面能否正常打开、离线图片能否识别，是不同的验收项目。
